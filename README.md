# GitOdile — feedback

**Git without the bite.** A friendly desktop Git client by
[@martinezelx](https://github.com/martinezelx).

This repository is the public issue tracker for GitOdile. The application's
source code is developed privately; everything here is about **reporting bugs
and requesting features**.

## English

**A GitHub account is required to submit a report. Reports are public.** You can
review and edit the form before submitting it; opening it does not create an issue.

### Report a bug

The best way is from inside the app: **More actions (⋯) → Report an issue**.
GitOdile fills in the available app, operating system, WebView and Git versions.
Unavailable values are omitted. Project paths, code and remote addresses are
not included.

You can also [open one here](https://github.com/martinezelx/gitodile-feedback/issues/new?template=bug.yml)
and paste that block yourself — **About → Copy system info** puts it on your
clipboard. If the app cannot open, describe your system and the version you
installed, if known.

### Request a feature

[Open a feature request](https://github.com/martinezelx/gitodile-feedback/issues/new?template=feature.yml).
Describe the problem you ran into before the solution you have in mind: GitOdile
aims to translate what a person is trying to do into safe Git operations, so the
underlying goal is the useful part.

### Before you post

- **Search first.** Someone may have hit the same thing already.
- **Never paste secrets.** No access tokens, no authenticated remote URLs, and
  no source code you are not free to share. Issues here are public and
  permanently indexed.
- **Security vulnerabilities do not belong in public issues.** See
  [SECURITY.md](SECURITY.md) for the private reporting channel.

### What this repository is not

There is no source code here, and there are no pull requests to send. Issues,
their labels and their milestones are the whole content.

## Español

**Necesitas una cuenta de GitHub para enviar un informe. Los informes son públicos.**
Puedes revisar y editar el formulario antes de enviarlo; abrirlo no crea una incidencia.

- Desde la aplicación: **Más acciones (⋯) → Reportar un problema**. Rellena las
  versiones disponibles de la aplicación, el sistema, el WebView y Git. Omite
  los datos no disponibles. No incluye rutas, código ni direcciones remotas del proyecto.
- [Reportar un problema](https://github.com/martinezelx/gitodile-feedback/issues/new?template=bug-es.yml)
  desde la web. Pega **Acerca de → Copiar información del sistema** si puedes
  abrir la aplicación; si no, describe tu sistema y la versión que instalaste.
- [Proponer una mejora](https://github.com/martinezelx/gitodile-feedback/issues/new?template=feature-es.yml).
  Explica qué intentabas hacer y qué resultado te gustaría conseguir.

Busca primero en las incidencias existentes. No incluyas contraseñas, tokens,
direcciones con credenciales ni código privado. Comunica las vulnerabilidades
por el canal privado de [SECURITY.md](SECURITY.md), nunca en una incidencia pública.

El código de la aplicación es privado. Este repositorio no contiene código de
la aplicación ni descargas.
