## Integration safety

- Bring another local or remote branch into the current branch with a preview,
  verified recovery and preserved history, including an empty merge.
- Resolve saved overlaps from Bring in changes or a diverged Get project
  changes in the existing resolver. Get and publish never publishes after a
  pause; finishing and publishing remain explicit choices.
- A failed handoff after a verified local change keeps recovery evidence and
  offers only Close. Both workflows refuse unsupported sparse checkouts and
  unavailable shared history before integration.
- Overlap previews explain prepared work, unsaved overlaps and local-file
  collisions before offering to start the merge.
- Large overlap previews retain unsaved-work blockers when the file list is
  shortened. A failed refresh after Get keeps recovery evidence and cannot
  retry the integration or publish automatically.
- Merge hooks and signers cannot cause an older combination to overwrite
  work they just changed; GitOdile asks for a fresh review first.
- Same-named tags no longer change the displayed branch or hide its upstream.
  An empty local Git identity correctly overrides an inherited identity and
  blocks finishing until it is configured.
