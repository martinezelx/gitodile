# GitOdile 0.5.0

<!-- gitodile-highlights:start -->
## Highlights

- When work overlaps, the merge pauses safely and Overlapping changes shows what each branch changed in every file: keep one side or edit it in your own app, then finish or abandon the merge.
- Bring another local or remote branch into yours, or get project changes when both sides have new versions, with a preview and a recovery point before anything changes.
- Diffs mark each change as one capsule, filled for additions and outlined for removals, show the exact words that changed, and the Markdown preview now opens in History too.
- Updates have one home in Settings, a dot on More actions says when a new version is waiting, and reporting an issue copies your report and opens the GitHub form in one step.

GitOdile 0.5.0 completes collaboration: overlapping changes are resolved inside
the app, other branches can be brought into yours, and getting project changes
works when both sides have new versions. Diffs and Markdown previews are
clearer, and updates have one home in Settings.

## Overlapping changes

- When a merge pauses because work overlaps, whoever started it, the
  Overlapping changes screen shows the branches involved and every affected
  file, with what each branch changed named by branch rather than "ours" and
  "theirs". Open it from Overview, Changes or the command palette.
- For each file, keep one whole side, delete it, or open it in its own
  application and come back; GitOdile says if conflict markers remain. Mark a
  file resolved, or reset it to the original overlap if you change your mind.
- Finish the merge through a plan that shows the saved version it creates, or
  abandon it through a plan that says what can and cannot be restored. A
  snapshot taken before the first change keeps what each action replaces.
- Folders in the way, case-only name collisions and unreadable paths explain
  what to do instead of failing. A paused rebase, cherry-pick, revert or stash
  pop started by another tool is explained read-only, with the commands to
  finish it there.
- Narrow the file list by pending or resolved state and by file extension.

## Bringing work together

- **Bring in changes** merges another local or remote branch into the current
  branch from Branches, the quick switch or the command palette. The preview
  says whether it is an advance, a merge version or an empty merge, and a
  verified recovery point is kept before anything changes.
- Get project changes now handles an upstream with new versions on both sides:
  branches that do not overlap are combined with a merge version, and saved
  overlaps can be opened in the resolver after a verified pause. Get and
  publish never publishes after a pause; finishing and publishing stay
  explicit.
- Previews explain prepared work, unsaved overlaps and local-file collisions
  before offering to start the merge, and keep unsaved-work blockers when a
  long file list is shortened.
- Merge hooks and signers can no longer cause an older combination to
  overwrite work they just changed; GitOdile asks for a fresh review first.
- Unsupported sparse checkouts and histories without a shared version are
  refused before integration. An outcome GitOdile cannot verify keeps its
  recovery evidence and offers only Close.
- Same-named tags no longer change the displayed branch or hide its upstream,
  and an empty local Git identity correctly overrides an inherited one.

## Changes and History

- Text diffs mark each run of changed lines as one capsule, filled for an
  addition and outlined for a removal, and a replacement flows from the removal
  into its addition. Additions and removals stay distinguishable without
  colour.
- Paired edits show the exact changed words and spacing, split views name the
  version each side shows, and the change arrows mark where they land.
- The Markdown preview opens in History too, comparing a version's document
  with the one before it. It shows the words a one-word edit changed, opens a
  long document on its changes with their section headings, fills a changed
  code block with its tint, and folds the rest away.
- The bar beside the totals in Overview's "What you'll save" uses the same
  capsule.

## Updates and reporting

- Settings › Updates is the one place an update is handled. The menu, the
  command palette, notifications, About and the startup notice all open it,
  and it shows the state, the next step, the progress and what the new version
  brings. Checking no longer opens a dialog that usually said you were up to
  date.
- When a version is waiting, More actions carries a dot and its entry names the
  next step, such as "Update to…" or "Install…".
- Report an issue copies the reviewed report and opens the prefilled GitHub form
  in one action, then a short step says what is left and lets you copy it
  again.

## Themes, console and projects

- In all twelve themes, "saved here", "done", the remote, warnings, danger, the
  favourite heart and GitOdile's violet can be told apart at a glance. Open
  folders no longer repeat their files' change kinds as dots.
- The console's mascot shrinks into the watermark when the first command runs
  and comes back when the console is cleared, and each command gets a brief
  blink.
- Returning to a project shows its actual branch and changes, a project's
  console survives visits to other projects, and restarting watching no longer
  misses new events.
- The status bar's project initials fit their badge, and History keeps the
  version strip while a version's details load.

## Project home

- Source, issues, releases and downloads now live in one public repository,
  [martinezelx/gitodile](https://github.com/martinezelx/gitodile). Installed
  versions keep receiving updates without any action, and earlier installers
  remain available for reinstalling.

## Packages

- Windows is provided as an NSIS installer. Authenticode remains deferred, so
  Windows may show an unknown-publisher or SmartScreen warning.
- Linux is provided as an AppImage. macOS packages remain deferred.
- Both packages verify updates with the production Tauri updater key and use
  the public update feed. Publishing this release does not declare either
  target qualified, and macOS, Linux and assistive-technology qualification of
  the new workflows remains open.
